The Seven Mental Models of Data Manipulation

The seven most important ways we manipulate datasets are:

  1. Assign: Add new variables with calculations and transformations
  2. Subset: Filter data based on conditions or select specific columns
  3. Drop: Remove unwanted variables or observations
  4. Sort: Arrange data by values or indices
  5. Aggregate: Summarize data using functions like mean, sum, count
  6. Merge: Combine information from multiple datasets
  7. Split-Apply-Combine: Group data and apply functions within groups

# Simple assignment - calculate if shipment was late
shipments_with_lateness = (
    shipments_df
    .assign(
        is_late=lambda df: df['actualShipDate'] > df['plannedShipDate'],
        days_late=lambda df: (df['actualShipDate'] - df['plannedShipDate']).dt.days
    )
)

Tip💡 Method Chaining Tip for New Python Users

Why use lambda df:? When chaining methods, we need to reference the current state of the dataframe. The lambda df: tells pandas “use the current dataframe in this calculation.” Without it, pandas would look for a variable called df that doesn’t exist.

Alternative approach: You could also write this as separate steps, but method chaining keeps related operations together and makes the code more readable.

Question 2: String vs Date Comparison - Can you give an example where comparing two dates as strings would yield unintuitive results, e.g. what happens if you try to compare “04-11-2025” and “05-20-2024” as strings vs as dates?

String is lexicographically compared, so “04-11-2025” > “05-20-2024” is False because “04” is less than “05”.

Datetime is chronologically compared, so “2025-04-11” > “2024-05-20” is True because “2025” is greater than “2024”.

# Date comparison (chronological)

  1. Format is another challenge. String comparisons depend on the format.
    • “2024-05-20” > “20-05-2024” is False because “2024” is less than “20”.
    • “05/20/2024” > “2024-05-20” is True because “05/20/2024” is greater than “2024-05-20”.
    • “2024-05-20” == “2024-5-20” is False because “05” is not equal to “5”.
    • “2024-05-20” == “2024-05-20” is False because Space in the end.

Question 2: Handling Missing Data - What happens if you use .dropna() without specifying subset? How is this different from .dropna(subset=['plannedShipDate', 'actualShipDate'])?

If you use .dropna() without specifying subset, it will drop all rows with any missing values in any column. If you use .dropna(subset=['plannedShipDate', 'actualShipDate']), it will drop rows with missing values in only the plannedShipDate and actualShipDate columns. This is more selective and efficient. - Why might you want to be selective about which columns to check for missing values? Data analysis is about focusing on the relevant columns and data. If you don’t need to check for missing values in all columns, it’s more efficient and easier to understand. Say each column is a feature and based on domain/context, you may not need to check for missing values in all columns. example if you are analyzing a dataset of customer orders, you may not need to check for missing values in the order created-by user column if you are only interested in the order amount.

Question 1: Boolean Aggregation - Why does sum() work on boolean values? What does it count?

Boolean values are either True or False. Here, true is 1 and false is 0. Sum is a function that adds up the values of a column, here it is adding up the number of True and False values. Question 1: Join Types and Data Loss - Why does your professor think we should use how='left' in most cases? - How can you check if any shipments were lost during the merge?

Left join keeps all records from left dataframe and and only joins the records from the right dataframe that have matching values in the key column. This is to avoid losing data. Inner join keeps only the records that have matching values in both dataframes. There is data loss if there are no matching values in the right dataframe. So, left join is more flexible and avoids data loss.

We can check if any shipments were lost during the merge by checking if the number of records in the left dataframe is the same as the number of records in the right dataframe after the merge.
